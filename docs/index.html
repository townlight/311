Townlight / Townlight 311

Resident requests routed without black-box dispatch.

Townlight 311 is the Townlight module for resident service-request intake, privacy-aware tracking, staff workflow, records, notifications, and Open311-compatible interchange. Townlight 311 0.2.0 is included in the signed Townlight for Windows 1.10.0.1 public beta.

0.2.0 — in the Windows 1.10.0.1 public beta

Release status — plain

  • Townlight 311 is included in the signed Townlight for Windows 1.10.0.1 public beta.
  • On two Windows PCs, a resident submitted a 311 request with a photo, followed its status and saw the public comment.
  • The staff workflow completed eight observed milestones across 311, Communications and Parks.

These results come from the release acceptance record. This is a public beta.

What Townlight 311 0.2.0 implements

  • Resident intake with resident photos and privacy-aware tracking; resident-facing tracking does not expose internal detail. The recovery flow is designed so staff never disclose another resident's data.
  • Department queues, assignment and transfer, staff lifecycle, duplicate handling, and reopen.
  • SMTP notifications with a durable outbox and states sent, pending, failed, and uncertain. Delivery is not guaranteed.
  • Open311 authenticated catalogue, read, and create with JSON/XML for the supported subset only. This is not full Open311 conformance.
  • CSV/JSON import up to 2 MiB and 1000 rows, keyed by stable external IDs plus a source key, with an exact preview hash. Export is capped at 10,000 requests; an export that would exceed the cap fails rather than truncating.
  • Records/Data output: ZIP archives report the actual bytes written plus the operation history.
  • Parks maintenance in the maintenance workflow.

Roles and Records/Data receiving

Existing native roles are local-admin, city-staff, and clerk. Clerk gets 311 only. Records/Data receiving requires additional permissions and is not granted automatically by the Clerk role.

Deployment requirements

The resident portal and SMTP must be separately deployed and configured. Notification delivery is not guaranteed; uncertain means delivery status is unknown after a send was attempted.

A placeholder checklist is not promoted as a workflow. Use the configured portal and SMTP setup for the environment.

Explicit limits

Townlight 311 does not dispatch crews, create official work orders, handle emergencies, provide legal advice, call live LLMs, write back to 311 systems, or replace a 311 system of record. Open311 support is the authenticated supported subset only; it is not full Open311 conformance.

FAQ

Q: Is this released?
Yes, as a public beta. Townlight 311 0.2.0 ships in the signed Windows 1.10.0.1 installer. The release acceptance record lists what was tested.

Q: How do I get it?
Install Townlight for Windows 1.10.0.1 from the GitHub release page. Townlight 311 is part of that installer.

Q: What about Townlight Suite 1.9.3.2?
That earlier release does not contain Townlight 311. Townlight for Windows 1.10.0.1 can upgrade it.

Q: Are delivery and integrations guaranteed?
No. SMTP notification delivery is not guaranteed. Open311 is limited to the supported subset, and the portal and SMTP require separate deployment and configuration.
